# Known limitations

**Version:** 1.0.0

These notes describe behavior verified in the current interpreter build. They may change in a later version. Do not rely on these limitations as permanent language guarantees.

- **`BREAK` and `CONTINUE` outside loops:** They are currently accepted and ignored at top level; execution continues with the next statement and no error is reported. This behavior may become an error in 2.0.0, so do not rely on it. See [the runnable example](examples/limitation-top-level-loop-control.vlt).
- **`RETURN` outside a function:** It is currently accepted at top level, its return state is ignored by module execution, and the next statement runs. This behavior may change; do not rely on it. See [the tested example](examples/statements-return-outside-function.vlt).
- **Non-`void` functions need not return on every path:** Current analysis accepts a non-`void` function if it finds a `RETURN` somewhere in the function body; it does not require every branch to return. If execution follows a path with no `RETURN`, the function currently produces a void value. This behavior may change in 2.0.0; do not rely on it. See [the tested example](examples/statements-return-not-on-all-paths.vlt).
- **Nested function definitions:** Current analysis accepts a `FUNCTION` definition inside an `IF`, a loop, or another function in the tested cases. This behavior may change in 2.0.0; do not rely on it. See the examples [inside an `IF`](examples/statements-function-in-if.vlt), [inside a loop](examples/statements-function-in-loop.vlt), and [inside another function](examples/statements-function-in-function.vlt).
- **Float-to-int conversion:** Assigning a `float` to an existing `int` variable currently converts silently by truncating toward zero (the variable example prints `2` for `2.5` and `-2` for `-2.9`). Passing a `float` to an `int` user-function parameter also currently truncates silently toward zero. These behaviors may change in 2.0.0. See the [variable assignment example](examples/variables-declare-reassign.vlt) and the [parameter example](examples/limitation-float-to-int-parameter.vlt).
- **Explicit conversion functions:** `int()`, `float()`, and `str()` are not currently available; tested calls produce `SyntaxError`. Their support is planned for 2.0.0, but the plan may change. See the tested [int form](examples/limitation-int-conversion.vlt) ([output](examples/limitation-int-conversion.expected)), [float form](examples/limitation-float-conversion.vlt) ([output](examples/limitation-float-conversion.expected)), and [str form](examples/limitation-str-conversion.vlt) ([output](examples/limitation-str-conversion.expected)).
- **Recursion and forward calls:** Self-recursive and mutually recursive function calls, as well as calls made before a function's definition, are currently rejected during semantic analysis. This describes current behavior and may change in a later version. See [self-recursion](examples/limitation-self-recursion.vlt), [mutual recursion](examples/limitation-mutual-recursion.vlt), and [forward call](examples/limitation-forward-call.vlt).
- **`IMPORT`:** Import statements are currently unsupported and produce a syntax error. Import support is planned for 2.0.0; this is a plan, not a guarantee of final behavior or timing. See [the runnable example](examples/limitation-import.vlt).
- **Variable inspection with shadowing:** `__INSPECT_VARS__` currently prints separate rows for same-named variables from parent and inner scopes. This follows from concatenating visible scope entries without deduplication; row order within a scope is not stable. The output may change in a later version. See [Variables: built-in names and inspection](variables.md#built-in-names-and-inspection).
